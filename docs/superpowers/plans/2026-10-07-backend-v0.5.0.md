# Backend v0.5.0 implementation plan

> Use the executing-plans skill, retain teammate edits and finish this version's
> source/tests/docs review before the independent push and hosted verification.

**Goal:** a useful sourced label report for barcode or corrected back fields.
**Architecture:** compose existing normalization, reviewed claims and exact source
resolution; automatic saving is a separately reported effect.
**Stack:** existing FastAPI/Pydantic/Firebase; no additional runtime dependency.

## Tasks and ownership

1. Root: write failing glossary tests, then bounded tracked name/function JSON and
   `backend/app/reports/glossary.py`. Verify supported English/Hindi aliases, INS
   subtype boundaries, unknown terms, original spans, hashes and invalid input.
2. Models/service worker: `backend/app/reports/{models,service}.py`, package and
   owned unit tests. Implement confirmed/barcode-less request, original normalized
   facts, selected-basis sugar, printed claims, source/declaration/missing-input
   sections and typed save outcome. Test uncertainty and historical blocking.
3. API worker: `app/api/v1/reports.py`, main/lifecycle/metadata/body limit and owned
   HTTP tests. Add report POST, exact GET and glossary GET (18 total routes);
   saving/auth failures preserve useful 200 analysis. Read-only GET source errors
   retain correct 404/503 and OFF-only availability.
4. Docs/export worker: current docs, tracker and contracts/export tests. Preserve
   historical OpenAPI and old strict models. Root owns version settings, encrypted
   env and version-specific review/release records.
5. Independently review each other's modules; root checks all maintained Python,
   tests/scripts, JSON, Markdown links and PowerShell entry points. Run full pytest,
   real emulator checks where storage changes justify them, Pyright, Ruff/format,
   dependency consistency, source build and actual setup. Reuse unchanged passing
   frontend checks unless frontend changes occur.
6. Update review/docs/settings before push. Commit/push v0.5.0 separately, verify
   exact READY deployment and hosted current/barcode-less/historical/glossary
   paths, saving/retry/ownership, source receipts and error boundaries. Clean
   synthetic records and Auth users. Publish a separate source-only release.

## Acceptance cases

- Ingredient-only/barcode-less report, insufficient claims and failed saving.
- Missing versus zero, mass/volume/measured/unmeasured serving distinction.
- Multiple tables without selection; conflicting/malformed/anomalous nutrients.
- Unknown/negated printed claims and unsupported claim families.
- Whole ingredient text and exact alias/code matching, no guessed allergen source.
- Historical catalogue claims remain unconfirmed.
- Knowledge or community outage preserves independent report sections.
- Actual API limits, strict numbers, redaction and metadata/contracts.
- Complete existing source hashes/receipts and historical contracts preserved.
