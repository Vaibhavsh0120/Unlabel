# Backend v0.2.0: nutrition facts and confirmed intake

**Goal:** Return usable nutrition facts while preserving the existing barcode API and the origin of every value. Implement only this accepted roadmap slice; Flutter remains v0.0.0.

**Architecture:** Two additive routes: `GET /v1/products/{barcode}/nutrition` adapts OFF v3.6 input tables; `POST /v1/nutrition/normalize` accepts bounded, user-confirmed public nutrient rows without an external call. A pure Python normalizer handles units and compatible quantity bases. No database, AI, image upload, health score or regulatory verdict.

**Stack:** Existing Python 3.12, FastAPI, Pydantic, HTTPX, pytest and Ruff; no additional dependencies or API keys.

## Boundaries

- Keep the strict v0.1.0 product response/schema unchanged. Export a separate v0.2.0 OpenAPI document and nutrition schemas/examples.
- Preserve table identity, source, preparation, original rows and units. OFF community data is never independently verified package evidence.
- Read finite numeric `value` entries from explicitly supported OFF input tables. Exclude computed/estimated/qualified values from exact facts; never use aggregated tables as label declarations.
- Canonical units: kcal for energy, g for mass nutrients. Convert kJ using 4.184 kJ/kcal; mg and ug to g. Convert known mass or volume quantities to 100 g or 100 mL, respectively. Unknown serving sizes stay per serving. Never infer density, added sugars, sodium from salt, or vice versa.
- Keep available carbohydrate separate from total carbohydrate. Missing nutrients remain null; zero is a reported value. Contradictory duplicate rows require correction.
- POST accepts only public structured label fields and random request/session UUIDs. Reject private/extra fields, unconfirmed rows, invalid numbers and duplicate IDs. Limit the actual request body to 32 KiB before parsing; validation responses omit submitted values. No persistence or raw-content logging.
- `complete` describes normalization of submitted rows, not nutritional completeness or food safety. Missing cells still carry reasons. Health analysis, claims, AI and comparison stay disabled.
- Deployments remain automatic from main to both existing Vercel projects. Update docs before each push, verify public production behavior, then publish backend v0.2.0. Preserve mobile artifacts/tags.
