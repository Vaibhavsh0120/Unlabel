# Backend v0.3.0 — reviewed confirmed-label claim checks

Prepared **7 October 2026** (Asia/Calcutta). Backend source is **0.3.0**; Flutter stays **0.0.0+1**. The preceding rich-facts backend v0.2.3 was pushed, hosted-verified and tagged independently. [Accepted two-version plan](../superpowers/plans/2026-10-06-backend-v0.2.3-v0.3.0.md) · [Current review](BACKEND_V0_3_0_REVIEW.md) · [Feature tracker](FEATURE_TRACKER.md).

This version makes a confirmed nutrition table usable for a small reviewed claim scope. `POST /v1/claims/check` returns numerical assessments for source/high fibre, low/sugar-free and low/very-low/sodium-free claims. Requests include strict confirmed rows, UUID session/request identifiers, correction revision, identified claims, selected table and food/form/preparation context. Missing information, conflicting inputs, unsupported applicability and unknown alternatives remain explicit. Recognized high/source protein, no-added-sugar and multigrain claims remain unreviewed and insufficient.

`GET /v1/claims/rules` returns seven loaded criteria and four unsupported claim types. `GET /v1/evidence/{source_id}` returns one of three reviewed source metadata records without fetching or serving a PDF. Knowledge **claims-2026-10-06.1** records Gazette/compendium provenance, acquired PDF hashes, page locators and review status. This scope checks numerical criteria for ordinary general foods; it provides no health score or full legal certification.

All claim thresholds use exact rational arithmetic from original numeric decimal strings and unit/basis factors, preserving boundaries even when a per-100 conversion is non-terminating. Fibre energy alternatives use statutory **4.2 kJ/kcal** and identify conversion version `fssai-schedule-i-note2-v1`. Normalization-v1 retains its separate scientific 4.184 factor. Conflicting regulatory energy values, unrepresentable output and known future publication/effective dates suppress affected assessments.

The network-free backend build now validates two approved knowledge JSON files and packages a verified hash/length receipt under ignored `app/claims/data/`, alongside the existing verified catalogue bundle. Hosted startup requires that receipt even for an explicit override; invalid knowledge disables only claim/rule/evidence access. Metadata reports actual capability/knowledge version and a verified `knowledge_artifact` receipt summary. No OFF, FSSAI or Gemini request runs during claim evaluation or bundling.

Existing product, nutrition, catalogue identity/facts/status and confirmed normalization contracts remain separate. Eleven current OpenAPI routes, five added model schemas and eleven validated owned synthetic examples support later client integration. Body-size/numeric-token/redacted-error boundaries cover both confirmed-input POST routes. Scripts and tests are updated for the combined build output; historical OpenAPI and tags remain unchanged.

Setup also gains dependency-free progress: measured catalogue verification bytes, indeterminate elapsed-work bars for terminal index/environment stages and plain dependency/Flutter stage logs. Completion follows actual validation; failures stop visibly, and noninteractive output uses plain lines without guessed percentages. The optional root-configured Pyright check covers maintained backend/scripts Python; it adds no runtime/npm-project dependency.

Final local validation passed **543 backend tests**, **59-file Pyright checking with zero errors/warnings**, Ruff/format/dependency checks, actual network-free two-bundle build and noninteractive backend setup. Independent review passed **150 focused tests** with no remaining findings; all Markdown/scripts were reviewed and demonstrably unused loader code removed. Flutter analysis reported zero issues and all **3 tests passed**, with its source unchanged. The [review](BACKEND_V0_3_0_REVIEW.md) separates these local gates from source push, exact-SHA Vercel verification and source-only publication. Production completion and publication are pending until recorded there. No APK/IPA workflow, paid service, card requirement or frontend API integration is introduced.

Camera/OCR, the full analysis report/score, ingredient glossary, comparison, saved/history/preferences and bilingual frontend flows remain tracked work. The claims feature is a partial implemented scope, not every claim shown in the design references.
